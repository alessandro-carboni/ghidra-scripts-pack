# Steps 10B.7–10B.9 — deterministic operational view

The explicit CLI commands operational-bind/local/canonical/fingerprint/compare are provided by the dedicated osgf_operational executable. rust_engine and cargo run retain the original v0.1 entrypoint. Shared legacy modules are imported by path, not copied or edited. Canonical and fingerprint loaders reconstruct their expected outputs from their source documents and reject modifications, including provenance/count changes. Outputs require new files.

## Normalization rules

| Rule ID | Preconditions | Input  ->  output | Justification / retained provenance | Positive and negative tests |
|---|---|---|---|---|
| OP-ID-01 | Validated contiguous extraction IDs and structural function mapping | Extraction-local IDs  ->  canonical-function/operation handles; original source in provenance | Remove function addresses from handles, retain every original instruction/sequence; no instruction reordering claim | Permuted operation/dependency arrays reproduce canonical bytes; forged canonical descriptor rejected |
| OP-STORAGE-01 | Pinned language, compiler specification and representation domain | Register identifiers and frame-relative stack slots retained; unique and absolute memory offsets excluded from descriptors | Register/stack roles cannot safely be erased before ABI-aware recovery. Unique producer identity is represented by links. Absolute memory/code locations are provenance only. No arbitrary alias equivalence or complete behavior claim | SUB input-order test originally failed after register/stack erasure; fixed representation, original assertion now passes. Width and source-reference validation retained |
| OP-CONST-01 | Observed constant bit vector and width | Hex leading zero removal, zero encoded as 0; exact remaining bits and width retained | Representation-only change, not numeric bucketing or signedness guessing | Real count-32 versus count-33 remains different; invalid oversized constants rejected |
| OP-COMM-01 | Exactly two equally wide operands; permitted opcode; appropriate output width | Sort operand descriptors; dependency input role becomes commutative, preserving edge multiplicity | Only ADD, MULT, bitwise AND/OR/XOR, EQUAL/NOTEQUAL and Boolean AND/OR/XOR are admitted. No SUB, shifts, inequalities, memory or phi reordering | ADD operand swap matches; SUB operand swap differs; signed predicates stay distinct |
| OP-ANALYSIS-01 | INDIRECT input slot 1 | Decompiler operation reference  ->  explicit analysis_reference marker | Handle is not a program constant. Full original operands remain in source/provenance. INDIRECT itself and its data dependencies are retained | Real MSVC/memory evidence validates; unknown operations remain explicit and qualify support |
| OP-ORDER-01 | Validated graph | Sort operations, dependency records, warnings, feature descriptors and occurrences | Deterministic document/feature order; source program sequencing not optimized away | Reordered source collections match; repeated CLI results identical |

No probabilistic transform, call-target invention, memory-effect elimination, interprocedural inlining or cross-architecture equivalence is performed. Storage-slot sensitivity is a conservative limitation to measure, not silently discard for better scores. Control destinations are not a full control-dependence graph. Unresolved inputs remain observable.

## Feature families

| Family | Information / targeted v0.1 gap | Differences distinguished / sensitivity | Cost, provenance, limitations |
|---|---|---|---|
| operation | Exact typed opcode, operand widths/kinds/constants/retained slots, output shape and structural role/distance | ADD/SUB, signed predicates, literals, LOAD/STORE; sensitive to compiler lowering and context | O(operations), occurrence points to original operation. Not full semantics; addresses excluded |
| dependency | Producer/consumer typed patterns plus input role | Operand flow, return/predicate consumers, effects sharing values | O(dependencies), two original operations per occurrence. Raw is local only; High is recovered SSA |
| two_edge_path | Bounded two-edge dependency paths with typed patterns and input roles | Different flow with same opcode histograms | Output budget max_two_edge_paths (default example 4096, ceiling 100000); three original operations per occurrence. Prefix truncation explicit; no unbounded expansion or equivalence proof |

Memory and return relationships are represented only when operations/links actually exist. No separate inferred alias, function-argument or source return-type summary is invented. A separate operational view preserves ablation against the unchanged structural three views. Counts equal retained occurrence multiplicities; feature IDs hash deterministic descriptors. Structural v0.1 fingerprint is generated by the unchanged implementation.

## Similarity and support

Operational set Jaccard = shared distinct descriptors / union distinct descriptors. Multiset Jaccard = sum minimum counts / sum maximum counts. Empty-empty is null; known complete empty versus nonempty is zero. Missing/unavailable extraction is not treated as a known semantic empty view. Incompatible representation/environment/configuration is rejected. Intermediate integer count sums use u128, including tests beyond u64 totals.

The structural comparison is performed by the existing v0.1 implementation, included explicitly as structural_v0_1. The combined research score is the unweighted arithmetic mean of comparable views; existing weights are not retuned. Missing feature records are qualified when evidence is incomplete. Self-comparison can score 1 with partial evidence: support fields retain the limitation.

Support reports feature counts, coverage, unavailable/partial functions, unsupported operations, unresolved inputs and path truncation. INSUFFICIENT_EVIDENCE means no operational descriptors; it is neither a probability nor a new automatic rejection/classification rule. decision remains null. Thin/generic descriptor sets can still tie at 1; final evaluation must report ties and feature sparsity. No validated classification policy is claimed by this library.

## Example configuration and commands (PowerShell)

Context JSON:
```json
{"structural":{"caller_depth":0,"callee_depth":2,"max_function_nodes":32,"max_total_nodes":256,"max_edges":512},"max_operational_functions":32,"max_operations":20000,"max_dependencies":40000}
```
Feature JSON: `{"max_two_edge_paths":4096}`.

```powershell
& rust_engine/operational/target/debug/osgf_operational.exe operational-bind typed.json high-evidence new-graph.json
& rust_engine/operational/target/debug/osgf_operational.exe operational-local new-graph.json fn:00401000 context.json new-local.json
& rust_engine/operational/target/debug/osgf_operational.exe operational-canonical new-local.json new-canonical.json
& rust_engine/operational/target/debug/osgf_operational.exe operational-fingerprint new-canonical.json features.json new-fingerprint.json
& rust_engine/operational/target/debug/osgf_operational.exe operational-compare new-fingerprint.json reference-fingerprint.json new-result.json
```

Use actual observed function IDs, not the example address. Both inputs retain canonical/source evidence and occurrence provenance. Old scientific fixtures and expected digests are unchanged.

Final packaging: build the isolated crate with `cargo build --locked --manifest-path rust_engine/operational/Cargo.toml`. It shares original source modules by path and uses the same locked third-party dependencies, while preserving the frozen original Cargo.toml/Cargo.lock and main.rs. CI has a dedicated operational-baseline job.
